# LifeOS reliability and CLI TODOs

Audit of the current checkout, 2026-10-31. Items below are open; an unchecked item is not a claim that a fix has shipped. This is a code audit, not an exhaustive runtime certification. References point to current implementation, and suspected behavior is labeled for verification. Keep personal data untouched while investigating.

## P0 — writes and transport

- [ ] **T01: Finish validating the shared mutation argument contract.** The desktop `transactional` boundary now copies plain JSON arguments, omits undefined object properties, preserves null and rejects unsupported values; `scripts/test_mutation_transport.mjs` checks the actual Solid client encoder with a mocked response. Verify each operation's missing-versus-null semantics and alignment with CLI, and exercise the real desktop-to-service path before closing this item.
- [ ] **T02: Repair affected save paths end to end.** Known examples include an Area without a description (`src/pages/Areas.tsx`), new habits and goals (`src/pages/Habits.tsx`), activity from a task (`src/features/items/ActivityLogControl.tsx`), creating or controlling recurrence (`src/features/items/RecurrenceControl.tsx`), a new automation (`src/pages/Automations.tsx`), attention corrections (`src/features/attention/TodayAttention.tsx`), and optional document, invoice, review and payment fields (`src/pages/Obligations.tsx`). Audit all other mutation call sites too; this list is evidence, not a guarantee of exhaustive runtime coverage.
- [ ] **T03: Verify Area form input and failure handling.** Area create/edit now keeps controlled name and description drafts through icon/color changes, waits for the save, and shows errors in both Area editors. Manually verify both routes and disconnect/retry behavior in the desktop.
- [ ] **T04: Verify Workspace form input and failure handling.** Workspace create/rename now await a reported result and keep the controlled name and error on failure. Manually verify both forms and service disconnect/retry in the desktop.
- [ ] **T05: Audit optimistic rollback and failed requests.** Areas, items and workspaces change optimistic state before awaiting the service and catch errors inside actions (`src/pages/Areas.tsx`, `src/features/items/context.tsx`, `src/features/workspaces/context.tsx`). Verify the actual Solid action rollback behavior when errors are caught, the request is rejected before sending, or the service disconnects. Confirm failed creates/edits/archive operations cannot leave phantom state and that retry preserves input. Do not assume rollback either succeeds or fails without reproducing it.
- [ ] **T06: Handle ambiguous success and safe retries.** `server/backend.mjs` commits a mutation before sending its snapshot response; a lost response or snapshot failure can leave a completed write that appears failed. Audit create/apply operations for idempotency and provide a way to check outcome or safely retry. Preserve existing activity-ID and payment-reference deduplication; do not duplicate tasks, template families or records after a retry.

## P1 — service, state, and compatibility

- [ ] **T07: Report real connection state.** `src/local/query.ts` currently returns `isWebSocketConnected: true` and `hasEverConnected: true` unconditionally. Wire connection/reconnect/failure state to the live service; make offline banners honest and ensure a stopped or ended stream cannot leave the UI falsely showing a healthy connection. Preserve unsent work.
- [ ] **T08: Handle service/client version mismatch.** `server/launcher.mjs` discovers an existing process by PID and a successful workspace query but does not compare its protocol/build compatibility; `service.json` has a constant version. An older background service may be reused after an installer update. Add an explicit compatibility handshake and safe restart/error path without terminating unrelated processes or losing in-flight work.
- [ ] **T09: Make updates and multi-step workflows explicit.** `src/pages/Obligations.tsx` now reports when a source was saved but extraction failed and retains the source for retry; the domain deduplicates the same source by kind/content. Verify this in the desktop, then audit other multi-step workflows for partial commits and safe retry.
- [ ] **T10: Decide and implement stale-write behavior.** Item, Area and Workspace updates accept `expectedUpdatedAt` (`src/local/api.ts`) but do not compare it before writing. Concurrent windows/CLI can overwrite newer changes. Either enforce conflict detection with an actionable UI/CLI error, or explicitly document a deliberate last-write-wins policy and its consequences.
- [ ] **T11: Refresh date-sensitive views across midnight.** `src/pages/Today.tsx` captures `localDateKey()` once when the page is created, so a long-running window can show the previous day after midnight. Refresh the task date and create action in local time without disturbing unsaved inputs; keep habit timezone behavior intact.
- [ ] **T12: Review snapshot cost and failure behavior.** Every successful mutation broadcasts a full serialized store snapshot (`server/backend.mjs`). Check behavior with realistic data volume, slow clients and concurrent writes; optimize only if evidence justifies it, while preserving transaction ordering, workspace boundaries and live updates.

## P1 — complete non-interactive CLI for automation

Goal: every supported LifeOS feature has a documented, non-interactive, machine-usable interface backed by the same service and domain rules as the desktop. Scripts must not need prompts or a GUI, and existing user data must not be reset.

- [ ] **C01: Inventory desktop-to-CLI parity.** Map each `api` read/mutation and service operation to a documented CLI command or supported `query`/`run` operation, covering areas, items/families, tags, workspaces, templates, recurring items, automation rules/history, projects/evidence, obligations/payments, attention, habits, goals, activity and startup settings. Mark unsupported actions explicitly; do not claim parity until mapped and verified. `server/backend.mjs` exposes more core operations than `server/launcher.mjs` allows through `run`; core Area/Item/Tag/Workspace CRUD is not fully covered by the current CLI.
- [ ] **C02: Provide scriptable input and discovery.** Support documented JSON input from arguments and stdin/file as appropriate, stable discoverable command/operation schemas and examples, and workspace selection without interactive prompts. Preserve argument boundaries and Windows/PowerShell quoting; never require opening an editor for structured input.
- [ ] **C03: Make output and failures automation-safe.** Define consistent `--json` success/error formats, stdout/stderr separation, exit codes, help/version behavior and flag placement. Current `server/launcher.mjs` handles `help`/`stop`/`connection` before parsing `--json`, so e.g. `--json help` and `--json stop` do not follow the normal path. Keep backwards compatibility where practical.
- [ ] **C04: Enforce workspace scoping throughout CLI queries and writes.** Generic `query` injects a workspace, but the `item` query in `server/backend.mjs` calls `api.items.get` by ID and that selector does not check workspace. Audit every generic and dedicated path, including ID-based operations and intentional workspace-management exceptions, so a selected workspace cannot accidentally target records from another.
- [ ] **C05: Make automation retries safe and observable.** Provide explicit IDs/idempotency or documented safe reconciliation for writes that may be retried after timeouts, clear conflict/validation failures, bounded timeouts and no hidden interactive fallback. Preserve exact currency/units and structured errors; never silently mark payment or work complete.
- [ ] **C06: Document and verify packaged CLI parity.** Cover CLI-only usage with the window closed, installed binary/service version agreement, named and generic operations, Windows paths and Unicode, stdout JSON, failures, workspace isolation and restart persistence; include representative workflows for each feature and cross-check results against desktop records. Do not rely only on `/api` shortcuts.
